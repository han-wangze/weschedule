## 2. 逐条对照

### B006 · 措辞差异

- 标注：`上课` / 2026-07-20 / 08:00
- 模型：`第一节课换教室` / 2026-07-20 / 08:00
- 日期、时间、地点全对，只是标题更具体。严格 2-gram 配对认不出（"上课"不在"第一节课换教室"里）。

### D009 · 措辞差异

- 标注：`升旗仪式` 07:00；`上课` 10:00（均 2026-07-20）
- 模型：`升旗仪式` 07:00；`第二节课改实验室` 10:00
- 第一条完全命中，第二条同上。

### B005 · 措辞差异

- 标注：`聚餐` / 2026-07-20 / 12:00
- 模型：`一起吃饭` / 2026-07-20 / 12:00
- 同义改写，2-gram 无交集。

### D007 · 偶发日期错

- 原文：周五下午2点答辩，紧接着4点导师见面（ref_date = 2026-07-17，**当天就是周五**）
- 标注：两条都是 2026-07-24（规则 2：周X 取严格晚于今天的下一个）
- 模型（本轮）：两条都给了 2026-07-17，即"当天"

**没有改提示词，因为复跑不稳定**：单独连跑 3 次，三次全部 2026-07-24 ✓。同一 prompt 三次全对说明它是波动，和"同一 prompt 两次运行差 2 条"是同一现象。加 few-shot 会影响其余 12 条含"周X"的语料，收益不明确。

### H002 · 口径未定义（排班说明）

- 原文：下周值班安排：周一到周三由大一同学负责，周四、周五轮到我们组。周四下午4点到6点在办公室整理物资，周五上午10点开例会，地点还是活动中心204。另外下周三前把本学期的报销单交到财务处，别拖。
- 标注（3 条）：`整理物资` 07-23 16:00；`例会` 07-24 10:00；`交报销单` 07-22 23:59（DDL）
- 模型（8 条）：额外拆出 `大一同学值班` ×3（07-20/21/22）、`我们组值班` ×2（07-23/24），其余 3 条全对

**这条不能算模型错，但也不能算标注错**：一条消息里"谁哪天值班"是排班说明，"我们组值班"对"我"来说确实是日程。标注当时按"叙述性内容不提取"处理，模型按"逐日展开"处理，两边都讲得通——**评测集缺一条关于排班类消息的口径**。

对产品的真实影响：用户会看到 5 条"值班"日程，确实烦。所以这条虽然归到"口径未定义"，仍然值得后续单独定义规则（比如：排班/值班只在明确指派给本人时提取）。

### H012 · 口径未定义（"下班前"）

- 原文：下周整体节奏：周一全天在外地出差；周二上午10点回公司开会，下午2点见客户；周四下午4点有个跨部门对齐；周五下班前把月度总结交上来。
- 标注（5 条）：`出差` 07-20（无钟点）；`开会` 07-21 10:00；`见客户` 07-21 14:00；`跨部门对齐` 07-23 16:00；`交月度总结` 07-24 **23:59**（DDL）
- 模型（5 条）：前 4 条全部命中（标题措辞略不同但都能配对）；最后一条给的是 **18:00**

**规则 5 说"截止日未给具体时间时填 23:59"，但"下班前"其实指向 18:00**。模型的理解更贴近原意，标注是机械套规则。这条暴露的是规则 5 的边界：它没有区分"纯日期型 DDL"（23:59 合理）和"有明确时点含义的表述"（下班前/放学前）。

## 4. 从这批失败里得出的结论

1. **短消息侧：失分主要是判罚口径，不是理解能力**（3 条全是措辞）
2. **长消息侧：暴露的是真问题 + 口径缺口各一半**——H002 的多报会直接变成用户体验噪音，"下班前"则说明规则 5 需要细分
3. **单条 badcase 不该直接驱动 prompt 改动**：D007 复跑 3 次全对就是反例。先跑 3 次看稳定性，成本 3 次调用
4. 标题生成偏"描述性"（"第一节课换教室"）而不是"概念性"（"上课"）。这不一定是缺点——描述性标题对用户信息量更大——所以处理方式是放宽配对，而不是把提示词往概念词上拧
